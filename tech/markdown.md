# Markdown

## What it is

Markdown is a plain-text format for writing documents. Simple marks turn into structure: `# Title` is a heading, `- item` is a bullet, `**bold**`, `` `code` `` for code, and `| a | b |` rows make a table. A viewer such as GitHub shows the formatted result; the file stays readable as plain text. Files end in `.md`.

## Why this repository uses it

The exercise ends in documents that people read and decide from: the capacity plan, the launch decision, the runbooks, the ownership page and the decision records. Plain text in the repository can be reviewed like code. Two of the documents are **generated** from measurements, so their numbers cannot be typed wrongly, and tests fail when a generated document differs from what the generator produces.

## Where it appears

| File | Role |
| --- | --- |
| `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md` | The reader's documentation. |
| `docs/capacity-plan.md` | **Generated** by `make plan-doc` from `docs/evidence/` (not present until `make run` has produced the evidence). |
| `docs/launch-decision.md` | **Generated** by `make review` (the decision, the checklist table, the conditions and the accepted risks). |
| `docs/runbooks/*.md` | `api.md`, `cpu-knee.md`, `pool-exhaustion.md`, `zone-loss.md`: Symptoms, Mitigate and Diagnose sections; `<!-- measured -->` blocks are rewritten with measured numbers. |
| `docs/ownership.md` | Roles, on-call, escalation. |
| `docs/adr/*.md` | Decision records. |
| `tech/*.md` | These notes. |

## How it works underneath

Markdown is just text. A **heading** is one to six `#` characters at the start of a line. A **table** has a header row, a separator row of dashes (`| --- | --- |`) and then one row per line, with cells split by `|`. An **HTML comment** `<!-- ... -->` is invisible in the rendered page but present in the file, which makes it a convenient marker for tools. The review reads these files as raw text; it does not render them.

## Walkthrough of this repository's use

### A generated decision document

```python
def markdown(items: list[ReviewItem], decision: Decision) -> str:
    """`docs/launch-decision.md`: the decision first, then the table, the conditions and the accepted risks."""
    lines = [
        "# Launch decision",
        "",
        "Generated by `make review` from the repository and the measured evidence in `docs/evidence/`. "
        "Do not edit by hand; `make test` fails when this file differs from what the review produces.",
        "",
        f"## Decision: {decision.value}",
        "",
    ]
    failures = conditions(items)
    if failures:
        lines += ["Conditions (each has an owner and a date):", ""]
        lines += [f"- {line}" for line in failures]
    else:
        lines.append("No condition: every item passed or is an accepted risk with an owner.")
    lines += ["", "## The checklist", "", "| Area | Verdict | Owner | Evidence |", "| --- | --- | --- | --- |"]
    for item in items:
        owner = item.owner or "-"
        lines.append(f"| {item.area} | {item.verdict.value} | {owner} | {item.evidence} |")
    risks = [item for item in items if item.verdict is Verdict.ACCEPTED_RISK]
    if risks:
        lines += ["", "## Accepted risks", ""]
        lines += [f"- **{item.area}** (owner: {item.owner}). Reopen when: {item.revisit_when}" for item in risks]
    return "\n".join(lines) + "\n"
```

`markdown(items, decision)` builds the document line by line in a Python list and joins it with newlines. It writes the title (`# Launch decision`), a sentence saying the file is generated and must not be edited by hand, the decision as an `##` heading, the conditions as a bulleted list (each with an owner and a date), a table of every checklist item, and a bulleted list of accepted risks (`**bold**` for the area). The header `| Area | Verdict | Owner | Evidence |` and the separator `| --- | --- | --- | --- |` make the table.

### A runbook with measured facts

```markdown
# Runbook: loss of a zone

## Symptoms

- `FleetBelowFullStrength` (ticket): fewer healthy instances than the fleet has. `FleetBelowPeakCapacity` (page): fewer
  than the minimum that carries the projected peak (both numbers are in the facts above).
- Dashboard panel "Healthy instances" drops by the size of a zone; edge p99 rises if the remaining instances are above
  their safe load.

## What is known

<!-- measured -->
The fleet is **8** instances over three zones (3/3/2). Losing the largest zone leaves **5**, and 5 instances at 450 requests a second carry the projected peak of 2000. `FleetBelowPeakCapacity` pages below **5** healthy instances and `FleetBelowFullStrength` opens a ticket below **8**.
<!-- /measured -->

This was run, not assumed: `make zone-loss` stops the largest zone and runs the projected peak on the survivors
(see `docs/capacity-plan.md`).
```

A runbook has three headings the review requires: **Symptoms**, **Mitigate** and **Diagnose** (`RUNBOOK_HEADINGS` in `application/readiness.py`; a runbook without all three fails the review). Backticks mark commands and alert names; `<http://localhost:47281/clusters>` is a link written as a bare URL in angle brackets. The block between `<!-- measured -->` and `<!-- /measured -->` is the part a program rewrites: `make plan-doc` replaces it with the measured knee, safe load, fleet size or pool size. Until the experiments have run, the block says "Run `make run` to measure this".

### The capacity plan is built the same way

```python
"""Render `docs/capacity-plan.md` from the measurements, so the plan's numbers cannot drift from the evidence."""

from __future__ import annotations

from typing import Any

from capacity.application.ports import EvidenceStore

REQUIRED = (
    "knee",
    "soak",
    "plan",
    "fleet-full",
    "fleet-zone-loss",
    "pool-sweep",
    "fleet-pool-naive",
    "fleet-pool-resized",
)


def missing(evidence: EvidenceStore) -> list[str]:
    """Names of the evidence documents the report needs that have not been produced yet."""
    return [name for name in REQUIRED if evidence.load(name) is None]


def render(evidence: EvidenceStore) -> str:
    """The capacity plan as Markdown: facts, the knee, the safe load, the formula, the fleet checks, the next "
    "bottleneck."""
    docs: dict[str, Any] = {name: evidence.load(name) for name in REQUIRED}
    return "\n".join(
        [
            *_header(docs["plan"]),
            *_knee_section(docs["knee"]),
            *_safe_load_section(docs["knee"], docs["soak"]),
            *_fleet_section(docs["plan"], docs["fleet-full"], docs["fleet-zone-loss"]),
            *_pool_section(docs["pool-sweep"], docs["fleet-pool-resized"]),
        ]
    )
```

`render(evidence)` joins sections: the header with the lesson's facts, the knee table, the safe-load section, the fleet checks and the pool section. `missing(evidence)` lists the evidence the report needs but does not have yet; the command stops with `missing evidence: ...; run make run` instead of writing a plan with invented numbers.

## Try it yourself

1. Open `docs/runbooks/zone-loss.md` in a Markdown viewer: headings, bullets, code and the table rendering are visible.
2. `grep -n '^## ' docs/runbooks/*.md` lists the headings of all runbooks: each has `Symptoms`, `Mitigate` and `Diagnose`.
3. `.venv/bin/capacity review` prints the review table; with no evidence it says `DON'T LAUNCH YET`.
4. `.venv/bin/capacity review --write` writes `docs/launch-decision.md` (then `git diff` shows what changed; run `git checkout docs/launch-decision.md` to undo).
5. `.venv/bin/python -m pytest tests/unit/test_readiness.py -q` shows tests that remove a heading from a runbook and expect the review to fail.

## Mistakes people make

- Editing a generated document by hand. The next generation overwrites it and a test fails.
- A runbook that says "see the dashboard" without the command to run.
- Tables with a different number of `|` in a row.
- Putting measured numbers in prose by hand; they drift from the evidence.
